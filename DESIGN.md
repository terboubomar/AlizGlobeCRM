# ALIZ GLOBE CRM — DESIGN.md
Version 2.0 · 2026-10-20

## Product truth
Aliz Globe Company operates a multi-brand restaurant group. The CRM is a group-level complaint operations system: customer QR submissions, agent-created phone complaint records, branch investigation, ownership, SLAs, refund approvals/verification, scheduling, and analytics. Existing cloud telephony and order management remain outside the CRM. No real customer data in the demo.

## Design direction
**Quiet command center / premium operations utility**. Arabic-first, true RTL application chrome; compact information density, well-aligned figures, practical grouping, strong task priority. A high-quality operating console should not look like a marketing landing page. Minimal gradients, no gratuitous blur, no nested cards, no random illustrations, no bounce animations. Distinctive quality comes from hierarchy, precision, legibility and workflow speed.

## Typography and layout
- Arabic: Cairo (fallback Tajawal/Noto Sans Arabic). Use font weights 400, 600, 700, 800. Avoid microscopic 10px labels in production; target 12px minimum and 14px body.
- Spacing scale: 4, 8, 12, 16, 24, 32, 40px.
- Radius: inputs 8px; buttons 10px; cards 15px; customer QR form 22px.
- Desktop: right-side persistent navigation ~254px; max content width ~1550px, tables responsive with horizontal scroll and stable columns.
- Mobile: navigation drawer with overlay; stack KPI cards; mobile-first customer QR complaint form.
- Target minimum 44×44px interactive hit areas; keyboard focus visible; input labels and validation present; reduced motion supported.

## Surface map and workflow priorities
1. Group dashboard: KPIs, urgent queue, brand scopes and trend; demo badges on mock metrics.
2. Agent intake: brand → branch → customer → external order ref → category → description → create. Show issue ticket on submit. Phone system separate.
3. Ticket list and detail: SLA countdown, responsible branch, accountable agent, acknowledgment, action evidence, closure and immutable timeline.
4. Refunds: **approved is not processed**; require an external transaction reference/evidence, role-authorized verification and customer communication.
5. QR admin: public branch link generated by secure backend in production, printable logo-led QR sheet, activation/suspension, per-brand theme.
6. Public mobile complaint page: specific brand logo, pre-selected branch, reason, contact, attachments, privacy notices, tracking ticket reference.
7. Scheduling: seven-agent roster and staffing coverage, paid breaks and shifts; no telephony controls.
8. Reports: filters by permitted scope, branch comparison with denominator when available, XLSX/CSV export and methodology definitions.

## Component primitives & 21st.dev procurement
21st.dev is a community source library (https://21st.dev/) rather than a uniform built-in dependency. **Search and inspect license / accessibility / bundle size before copying.** Use Lucide icons consistently (line style, 18–20px, stroke ~1.8), with RTL-correct directional icons. Recommended component patterns to evaluate in the production React implementation: navigation/sidebar, command palette, data table, tabs, select/combobox, accessible dialog/sheet, toast, badges, calendar, upload dropzone and pagination. Prefer shadcn/ui + Radix primitives if registry assets are unsuitable. The standalone HTML demo keeps zero mandatory JS dependencies and uses lightweight text glyphs.

## Four reference workflows (research used to inform our conventions; not claiming their packages are installed)
### 1. Taste Skill — https://github.com/Leonxlnx/taste-skill
Run an app-specific design pass using `design-taste-frontend`, shape dashboard + forms for real operator tasks, inspect responsive frames at phone/tablet/desktop and iterate. Installation in dev environment: `npx skills add https://github.com/Leonxlnx/taste-skill --skill "design-taste-frontend"`.

### 2. Impeccable — https://github.com/pbakaus/impeccable
Run `npx impeccable install`, `/impeccable init`, `/impeccable audit`, `/impeccable critique` and `/impeccable polish`. Create and maintain durable `PRODUCT.md` and `DESIGN.md`. Focus on a11y, overflow, loading states, contrast and removal of template-looking elements. **Not executed in current package**.

### 3. Awesome DESIGN.md — https://github.com/voltagent/awesome-design-md
Treat this `DESIGN.md` as the authoritative visual contract read by all agents alongside `AGENTS.md`. Extract patterns as guidance, not as wholesale visual imitation. Reuse shared typography / spacing / component rules and explain divergences.

### 4. 21st.dev — https://21st.dev/ and https://github.com/21st-dev/skill
Use the 21st registry to search before hand-authoring specialized React components; copy permitted component source into project rather than assuming it is an npm UI runtime. Document dependencies and icon licenses. Practical CLI research: `21st search "sidebar" --type c`, `21st search "data table" --type c` (after installing its CLI in dev environment). Adapt to our brand tokens and RTL behavior.

## Quality gates before deployment
- Screenshot acceptance at 1440×900, 1024×768, 390×844 and 360×780.
- No horizontal overflow on public complaint form or mobile agent panels.
- Table and chart tooltips keyboard accessible; status not color-only.
- Brand logo sharp, uncropped, proportional and uses original bytes.
- Full RTL icon orientation, truncation of long brand names, phone numbers LTR where appropriate.
- At least WCAG 2.2 AA contrast and keyboard operation, to be measured in actual implementation.
- Form includes proper validation, error/success/saving states, and server-side rules before production. Prototype interactions do not certify production readiness.
- Run functional Playwright tests against each page and verify per-role authorization using backend test fixtures.
