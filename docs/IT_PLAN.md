# IT plan (D08)

Decided on 2026-10-25 by engineering acting as the group's IT team, on the owner's instruction. Items marked **owner** need someone who can sign a contract or hold an account; everything else is set here and in code.

## Backups and recovery targets

- **RPO 15 minutes, RTO 4 hours** for the database.
- Cloud SQL automated daily backups kept 30 days, plus point-in-time recovery (7 days of write-ahead logs).
- Daily logical export (`pg_dump -Fc`) to a separate bucket with a 35-day retention lock, so a compromised app account cannot delete backups.
- Photos: object versioning on, noncurrent versions kept 30 days.
- Restore is rehearsed monthly on staging (`npm run backup:rehearse`; CI runs the same rehearsal on every change). A release is not "done" until its rollback is rehearsed on staging.

## Alerts (Cloud Monitoring, to the on-call channel)

- Any `"level":"error"` line from the API or worker (5-minute window).
- `job_failed` from the worker, or no `retention_run`/SLA tick for 30 minutes.
- `malware_scan_failed` (scanner down: uploads are refusing) and any `malware_rejected`.
- Rate of HTTP 5xx above 1% for 5 minutes; `/api/health` failing from the load balancer.
- Database CPU above 80% or storage above 80%; Redis memory above 80%.

## What the owner provides

1. A CNTXT/Google Cloud billing account for the group (or approval to use Oracle instead).
2. The group domain and DNS access.
3. A Microsoft Entra ID tenant admin (or approval to run Keycloak).
4. Two named people to hold the offline copies of the encryption keys.
